# vibeCoding 教程章节生成模板

> 用途：生成《Vibe Coding 工程化》任意章节（共享单元 S0/S-A/…、B1/B2/B3 各步骤）时的**统一写作规范**。每生成一章，严格按此模板执行，保证全教程风格一致、方法可复用。
> 使用方：本教程所有后续文档生成（含 B1-③④⑤、B2、B3 各章节）。

---

## 〇、总纲约束（横切所有章节的灵魂与前提，先于骨架执行）

> 本节是**每条轨道、每个共享单元都必须体现的横切约束**，先于"一、骨架"执行。它不是五件套的替代，而是给所有章节钉死"教什么、不教什么"。

**约束 A · 灵魂 = 判断力（本节必体现，不只给操作）**

- 本章教的每个方法，都必须落到三问：**何时用**、**怎么在对话里识别 AI 的坑**、**怎么剪裁到本轮够用**——而不是只写"怎么操作"。
- 凡涉及排查 / 决策（如 B2 定位根因、B3 识别坏味道、B1 方案风险），须明确**区分"症状 vs 根因"**，并防 AI 幻觉（可回链 `S-A` 校验三招）。
- 验收清单要能证明"读者学完会判断"，而非"读者照抄了一遍"（见「六、验收清单规矩」）。

**约束 B · 默认读者有基础（前提约束，不铺基础知识）**

- 读者已满足基础自测第一、二档（读代码 / 跑程序 / 改代码）。各章**不得再写"什么是函数/循环/对象"等基础铺垫**，内容极度务实。
- 若要兜底或分层（新手/老手差异化），**一律不做成正文内嵌旁路块**，而是下沉到导读「三条路线图」（新手路线/老手路线），正文只留一行 🧭 指针指向它（见「一、骨架」第 3 步）；保持"省步骤 ≠ 省产出物、跳过的正是返工回来补的"纪律。正文不铺 `🪜`/`🟡` 逃生口块（符号收敛见「八、正文标记与符号收敛规范」）。

## 一、章节文档通用骨架（每章固定顺序，缺一不可）

1. **顶部元信息引用块**：`> **轨道**` `> **前置**` `> **目标**` `> **预估时长**`
2. **开篇"为什么"**：接续全教程贯穿案例或翻车教训，点明本章解决什么问题、值什么钱。
3. **每章开头一行「🧭 指针」（正文净化后唯一的分层载体，放在"本章目标"之后、第一节之前）**：
   - 写法（照抄，把 `X` / `①②③` / 可跳节按本章实际填)：
     `> 🧭 本章怎么读：主线走完全程（约 X 分钟）；想只先跑通？→ 本章最少做"①②③"，见导读「三条路线图」·新手路线；只想看核心方法？→ 见导读 ·老手路线。本章可跳：(列 2–3 节)。省步骤 ≠ 省产出物，跳过的正是返工回来补的。`
   - 性质：**一行即指针，不再允许把"新手最低可行 / 选学 / 逃生口"写成正文内嵌旁路块**；分层细节统一由导读「三条路线图」承载（新手/老手两条线）。
   - 红线：**只能一行**，不许展开成块（否则退回旁路块）；每章只此一行，不重复铺 `🪜`/`🟡`/`🆘`。
   - 卡壳兜底：**不逐章铺卡壳救助站**，正文仅留一行指针 → "读不懂？把本节原文丢给 AI，话术见导读「读不懂？用 AI 帮你读本教程」"（见「八」）。
4. **通用方法主体**：核心写法见「二」，这是全章重头。
5. **沉淀成「产出物」（本步的产出物锚定）**：**每章必须有**。明确"本章要交出一份什么样的东西"——像 B1-① 的"需求文档六要素"那样，给该阶段产出的**文档/清单结构样本 + 怎么写 + 检查标准**，并配一条**整合提示词**，把 二、里各方法小节的「产出」统一整理成这份规范交付物。它是下一章前置里"以 XX 为输入"的落点，也保证输入-输出前后衔接。
6. **提示词模板 + 逐字段解析**：完整给出可复制的提示词，并逐个字段说明作用、何时追加追问。
7. **练习**：给步骤 + "对答案"/"完成标准"。
8. **本章验收清单**：每条以 `[ ]` 开头，具体可核验，非空话。
9. **结尾"下一步"**：指向下一环节（用 `> ✅ 通过后，进入 …`）。

## 二、通用方法段的统一五件套（核心规范）

每个"方法 / 设计产物"一律按下面五件套展开，顺序固定：

1. **产出** —— 小节第一行必须是「**产出**：…」，用一句话声明这个小节递出一份什么（一份清单 / 表格 / 文档等）。这是全教程的核心约定：**每个通用方法小节都以"产出"开头**（如 B1-① 目标一产出五维清单、目标二产出验收标准、目标三产出范围边界）。
2. **可复制的拆分维度** —— 用表格：`| 维度 | 核心问题 | 装进「贯穿案例」|`，列出的维度必须**跨需求通用、可复制套用**。
3. **照抄即用的通用追问提示词** —— 放在引用块 `>` 里，用 `[占位]` 让读者把词一换就能直接丢给 AI/自己用。一定是"问 AI 的 prompt/流程"，**不是产出物模板**。
4. **关键判断** —— 用 `> 💡` 标出"何时做 / 怎么防漏 / 怎么核验"这类可操作判定。

> 四大铁律：
> - 每个方法小节**先声明"产出"**，再教怎么做；不规定产出，等于没有交付目标。
> - 维度可复制、提示词照抄即用 → 让读者"知其所以然 + 能照着做"；
> - 贯穿案例**只作点睛**，出现在"装进栏"或一两句示例，**不喧宾夺主**；
> - 避免只给成品示例而不给通用流程（读者会反馈"只知其然不知其所以然"）。

> 📎 各小节的「产出」由「沉淀成产出物」环节用一条**整合提示词**统一整理成下一章要用的规范交付文档，产出链条由此闭合。

> 🧭 **轻量/逃生口不再内嵌正文（重方法章节改走指针）**：当某个共享单元/轨道步骤方法较重（要读懂整个系统、要走完整流程），其新手逃生口（案例：S0 的"5 步最小闭环"、S-A 的"狙击手模式 S-1-Lite"）**下沉到导读「三条路线图」·新手路线**，正文只在该章开头指针里指向它，不在方法段内再铺逃生口块。要求：**主线保持完整** + 保留"省步骤 ≠ 省产出物"纪律；逃生口对应提示词仍先在 S-附录 登记（如 S-1-Lite）再被引用。

## 三、贯穿案例

- **主线贯穿案例**：电商订单退款（全教程一致复用，不重复展开）。
- **点睛原则**：案例只出现在拆分维度表的"装进「退款」"列、或一句简短示例；主体是通用维度+通用提示词。
- **判断训练点睛（增值，可选但推荐）**：案例除演示"通用维度"外，还可作**判断训练素材**——例如"读这行代码，你会先怀疑哪一步错了？""这个退款金额存哪里？数据第一次变不对在哪？"用退款案例引读者主动判断，而非只给答案。目标是把案例从"示例"升级为"练判断力的靶子"。

---

## 四、风格与质量标准

- **中文**：全部输出中文。
- **详细深入、具体可执行**：给结论必须给"怎么做/怎么判断"，逐项可操作。
- **"知其然 → 知其所以然"**：先给通用方法，再给判断依据，不堆砌成品。
- **验收清单**：逐条可核验、可打勾，不写"体验要好"这类主观空话。

---

## 五、提示词模板段规矩（S-附录）

- 完整复述可填空的正式提示词。
- **逐字段解析**：每个 `[占位]` 说明其作用，以及什么场景要追加什么追问。
- 常给"递归用法"（如把第一版结果回喂 AI 迭代）。
- **选填（选项式澄清）收敛，正文不铺 🔽 大块**：凡提示词需要读者**自己产出答案或拍一个选择**、且初学易卡壳的，2~3 个默认选项**统一在 S-附录 登记**；正文提示词处只写一行引用（→ "选填兜底见 S-附录 · 全量提示词模板库 对应编号条目，标 🔽 即高发，照抄即用"），**不在正文末尾展开成 🔽 大块**。只降门槛、不替人拍板；通用兜底话术见 S-附录"进阶操作速记"第四条"选填"；高发条目在 S-附录 里标 `🔽`。

---

## 六、验收清单规矩

- 每条 `[ ] 我能…` 开头，具体、可操作。
- 覆盖本章所有核心知识点。
- **必含"判断力"一条**：`[ ] 我能判断……（而非只会照抄操作）`——例如"我能判断该用哪个方法 / 识别出 AI 的坑 / 区分症状与根因"。若本条无法填写，说明本章只教了操作、缺了灵魂，需回头补判断训练。
- 末尾用 `> ✅` 提示通过后进入的环节。

---

## 七、文件夹与命名惯例

- 每章一个 `.md` 文件，按"区 + 轨道"分层归入对应子文件夹（见 `00-导读/README.md` 的目录索引）。
- 顶层目录用数字前缀固定顺序：`00-导读` → `10-共享单元` → `20-工具库` → `30-B1` → `40-B2` → `50-B3` → `写作规范` → `大纲`。
- 目录名含 `/`、`（）` 等非法字符时，用全角字替代或以无歧义语义名命名（如 `30-B1通用需求轨道` 不用括号）。
- 文件命名遵循轨道编号：`B1①-需求澄清与分析.md`、`S-A-现状探索.md`。
- 新增轨道/章节：先建带编号前缀的目录（`4x-Bx`），按相同惯例放文件，并在 README 索引同步登记。

## 八、正文标记与符号收敛规范（净化后正文只留判断力标记）

正文只容忍两类标记，其余一律**逐出正文、归入各自归宿**：

| 处置 | 标记 | 用途与约束 |
|---|---|---|
| ✅ 保留为主线 | `💡` 关键判断 | 何时做 / 识别 AI 的坑 / 剪裁到够用；逐条可核验 |
| ✅ 保留（并入主线，不单独成"块"） | `🔴` 必学重点 | 融入主线论述 |
| ⏬ 下沉导读「三条路线图」·新手/老手路线 | `🪜` `🟡` 选学·分层 | 正文不留块，只在开头指针里指向路线图 |
| ⏬ 归位导读「读不懂？用 AI 帮你读本教程」 | `🆘` 卡壳救助 | 正文不逐章铺救助站，仅留一行指针指向该导读节 |
| ⏬ 收敛进 S-附录（提示词处只留编号引用） | `🔽` 选填兜底 | 正文不展开 🔽 大块，写"选填见 S-附录 对应 🔽 条目" |

三条归一：

1. **载体不再是"块"**：分层 / 兜底 / 选填从"每章内嵌段落"收敛为"一行指针 / 一句引用"，信息平移进导读与 S-附录，不因改形态而删信息。
2. **引导统一指向导读**：正文只留"判断力 + 产出物 + 指针"；"我该走哪条路 / 读不懂怎么办"统一由导读承载。
3. **少记一套标签**：读者不再需要认识 `🪜🟡🆘🔽`，注意力还给判断力（💡 / 🔴）。

> 写任何新章时，若想用某个旁路块，一律先问"它的信息该下沉到哪条路线 / 归位到哪个导读节 / 登记进哪条 S-附录"——而不是把它塞进正文。
