## 一、为什么"每步绿"还不够，要单独做一次"整体保真确认"？

| | 只看"每步都绿" | 再做整体保真确认 |
|---|---|---|
| 覆盖 | 每步局部 | 全量 + 逐样本整体比对 |
| 意外 | 步内可控，跨步组合可能翻车 | 一次总账兜底 |
| 漏/多改 | 容易忽略"忘了删"或"顺手加了" | 复核清点抓漏/多 |
| 留档 | 零散记录 | 一份"行为零变化"收据 |
| 未来回看 | 说不清变了没 | 明确"仅内部结构变化" |

> 一句话：**每步绿是过程信任，整体保真确认是结果收据。** B3 真正交付的价值就是"行为没变"，这个必须得到证。

## 二、通用方法：总账式地确认"行为零变化"并收尾

### 🔴 目标一：全量保真——重跑基线，逐样本对比无变化

**产出**：一份**保真确认结论**——重构后重跑行为基线对应全部测试全绿，并列出"与 B3-① 基线对比，无任何输入输出样本变化"。

**要确认的本质**：不是"测试跑绿"就完事，而是**和 B3-① 拍的"重构前照片"逐张比对**——同一批输入样本，重构前后的输出要完全一致。这才是"行为没变"的可核验定义。复跑全量（不只刚才改动的那几处）防"改动波及到没测到的地方"。

**可复制的拆分维度**：

| 维度 | 核心问题 | 装进「handler 样板」 |
|------|----------|----------------------|
| **全量跑** | 重跑哪些测试？ | `go test ./...` 全量（含 3 个 handler） |
| **逐样本** | 同样本前后输出一致？ | create 200 响应体、400 文案、404 语义 |
| **对比对象** | 跟什么比？ | 与 B3-①"行为基线说明"的断言逐条核对 |
| **无损证据** | 怎么证明零变化？ | "任何输入输出样本都无变化"+ 全绿输出 |

**怎么让"逐样本比对"不靠肉眼，还能自动重跑？——翻译成 golden 断言**：把 B3-① 基线里的"同一批输入样本 → 预期输出"明明白白写进测试，做成**表驱动**：每个样本给"输入 → 预期输出"一行，`go test` 跑的时候自动断言实际输出 == 预期输出。这样：
- 重构前先跑一遍，测试绿（预期 = 现状，即 golden）；
- 重构后重跑同一测试，若输出变了 → 断言**自动红**，立刻抓住"行为被改坏"；
- 之后再有任何改动，这条 golden 测试都是"守门员"，不用每次人工肉眼比对。

**照抄即用的通用追问提示词**（即 S-附录 **B3-5** 的 ①）：

> 跑一遍行为基线对应的全部测试，做「全量保真」确认：
> · 重跑 `[测试命令，如 go test ./...]` 全绿；
> · 与 B3-① 行为基线说明逐样本比对，列出"无任何输入输出样本变化"；
> · 给出结论：行为是否与重构前完全一致。

> 💡 **关键判断**：保真的合格线 = **"全量测试全绿 + 与 B3-① 基线逐样本对比零变化"**。若某样本输出有变，就是真改坏了行为（不是测试跑不过），必须回 B3-④ 处理，不能看作"测试要改"。

### 🔴 目标二：复核清点 + 文档同步 + 收尾结论

**产出**：一份**收尾结论**——复核 B3-③ 重构方案有没有漏改/多改、把 CHANGELOG 与接口说明同步成"仅内部结构变化"、给出一句"保真通过 / 发现偏差"的总结论。

**要清点的本质**：重构收尾要"对得上账"——方案里列的每一处，改了没、验了没；同时确认**没有多改**（比如顺手动了不该动的逻辑）。文档侧要复用 S-C：CHANGELOG 记"重构（行为不变）"，接口/结构说明更新为"仅内部结构变化"。

> 📌 **文档同步的落地话术（S-C 的 S-8/S-10 内联摘要，照抄即可）**：①**CHANGELOG**：新增一条 `[1.0.0]`，section 用「变更」，条目写"重构（行为不变）：<手法，如 抽出 bindJSON helper / 拆分 migrations+版本表 / CalcRemaining 拆守卫拆分支>"；②**接口说明**：在 `docs/api-reference.md` 顶部加一行"（基准）重构：仅内部结构变化，REST 语义与金额规则不变"，正文契约**零改动**（可 `git diff docs/api-reference.md` 核对除该行外无 diff）；③兜底：若需完整方法论，见 S-C · S-8（同步代码到过时文档）/ S-10（更新 CHANGELOG）。

**可复制的拆分维度**：

| 维度 | 核心问题 | 装进「schema 演进」 |
|------|----------|----------------------|
| **漏改** | 方案里的都改了没？ | 3 处坏味道都重构完、验证过 |
| **多改** | 有没有顺手改不愿改的？ | 无——schema 只拆文件未动表结构 |
| **CHANGELOG** | 记一条？ | "重构：schema 拆分迁移文件（行为不变）" |
| **接口说明** | 更新为仅内部变化？ | README/接口 doc 注明 REST 语义未变、仅内部演进 |

**照抄即用的通用追问提示词**（即 S-附录 **B3-5** 的 ②③④）：

> 收尾清点 + 文档同步：
> · 对照 B3-③ 重构方案逐项勾选：改了没 / 验了没，有没有漏改 / 多改，漏的标红；
> · 复用 S-C：CHANGELOG 写一条"重构（行为不变）"，相关接口/结构说明更新为"仅内部结构变化"；
> · 给一句收尾结论："行为保真确认通过 / 发现偏差（列出并回 B3-④ 处理）"。

> 💡 **关键判断 · 三个"收尾必答"**：①**没漏改**（方案每处都改了且验了）②**没多改**（只动了方案内的，没顺手加功能/改逻辑）③**文档同步**（CHANGELOG + 接口说明标"仅内部结构变化"）。三者齐，才算"B3 收据"开全；发现偏差，回 B3-④ 最小回退重做，别自补丁盖过。

> 保真偏差一脸懵也别慌：把"发现保真偏差，先别让我改任何东西：①定位这个变化涉及重构方案的哪一处、哪个小步；②判断是'重构改坏了行为'还是'这行为本来就该是 B1 需求/隐性 bug 的事'；③给出回退重做的最小范围"给 AI——从"慌了乱改"变"先定位、再按 B3-④ 最小回退"；读不懂某节原文时，话术见导读「读不懂？用 AI 帮你读本教程」（卡壳救助已收拢于此）。

## 三、把收尾结果沉淀成「保真确认结论」（本步的产出物锚定）

你这一章要"交出去"的，是一份**保真确认结论**——全量保真全绿 + 与 B3-① 基线逐样本零变化 + 复核无漏/多改 + 文章档同步。它是 B3 轨道这次重构的"收据"，也是 B3 全链的闭环落点。固定结构：

```markdown
# 保真确认结论：<重构范围>

## 1. 全量保真
- 命令：`go test ./...` ✅ 全绿
- 与 B3-① 基线逐样本比对：无任何输入输出样本变化
- 高风险处（CalcRemaining）：补硬后的金额基线（≥8 条样本、覆盖四类，示例建议条数）全绿，输出与重构前一致

## 2. 复核清点
| 重构点（B3-③方案） | 改了没 | 验了没 | 多改? |
|---------------------|--------|--------|-------|
| handler 去重 | ✅ | ✅ | 否 |
| schema 拆分迁移 | ✅ | ✅ | 否 |
| CalcRemaining 拆分支 | ✅ | ✅ | 否 |

## 3. 文档同步
- CHANGELOG：`重构：handler 抽取 helper / schema 拆分迁移 / 规则拆守卫（行为不变）`
- 接口/结构说明：仅内部结构变化，REST 语义与金额规则不变

## 4. 收尾结论
行为保真确认通过，B3 轨道本次重构闭环。
```

**怎么写（从二、的四样产出拼）？**
- **"全量保真"**：取 目标一 的全量测试输出 + 逐样本比对结果。
- **"复核清点"**：取 目标二 的漏/多改勾选表。
- **"文档同步"**：取 目标二 的 CHANGELOG / 接口说明更新记录。
- **"收尾结论"**：取 目标二 的一句总结论（通过 / 有偏差及处理）。

**检查标准**：读这份结论的人，能确认"重构后行为与重构前完全一致、方案每处都改完验过、文档已同步、无多改"。**没给出"逐样本零变化"和"复核无漏/多改"的收尾，等于没开 B3 的收据**——它降级成了"测试好像都过了"的一句话说辞。

**整合提示词**（把二、的两份产出收拢成保真确认结论）：

> 请把下面几份产出整理成一份「保真确认结论」：
> [粘贴：全量保真输出 + 逐样本比对][粘贴：复核清点表][粘贴：CHANGELOG / 接口说明同步]
> 按 全量保真 / 复核清点 / 文档同步 / 收尾结论 四段输出，命令可复现全绿。输出 Markdown。

> 📌 这份"保真确认结论"是 **B3 轨道的交付收据**——它承接 B3-① 的行为基线、印证 B3-②~④ 每一步的改造都守住"行为零变化"。**至此 B3 轨道五章首尾相接、闭环完成**；后续再改 refund-shop 时，改完重跑的就是这套基线了。

> 💡 **递归用法**：AI 常把"测试全绿"误当成"保真"完事、跳过逐样本对比。**把它回馈，追加"把 B3-① 基线里的关键输入输出样本逐条列出来，重跑后逐条打勾'前后一致'，任何样本输出变了就标红，别只说'全绿'"**，迭代 1–2 轮直到"逐样本 + 无变化"坐实。

## 五、练习：为 handler 去重做保真确认并收尾

**任务**：在 main 分支，对已重构完成的 handler 去重（B3-④做的），做完整的保真确认并收尾出结论。

**推荐步骤**：

1. 用 B3-5 提示词，粘贴逐步重构记录 + B3-① handler 行为基线说明。
2. 让 AI 跑全量 `go test ./...`，并**逐样本**比对话重构前的 handler 基线（createOrder / createRefund / approveRefund 的返回体、400/404 语义）。
3. 复核清点：对照 B3-③ 的 handler 去重方案，勾选"改了没 / 验了没 / 多改?"。
4. 让它同步 CHANGELOG（"重构：handler 抽取 helper（行为不变）"）与接口说明（REST 语义未变、仅内部精简）。
5. 用整合提示词产出「保真确认结论」。

**对答案**：一份合格的保真确认结论应含四段，且**"逐样本比对无变化"被明确列出**，不只是"测试全绿"。

- **全量保真**：`go test ./...` 全绿；createOrder / createRefund / approveRefund 的返回体、400/404 语义均与 B3-① 基线逐条一致，**无任何输入输出样本变化**。
- **复核清点**：handler 去重 3 点（加分发 helper / 替换 3 handler / 删冗余）都"改了 ✅ 验了 ✅"，**无多改**。
- **文档同步**：CHANGELOG 写"重构：handler 抽取 helper（行为不变）"，README/接口说明注明"REST 语义未变、仅内部结构精简"。
- **收尾结论**：行为保真确认通过，handler 去重本次重构闭环。

> 🔎 **（可选进阶）体会"全绿 ≠ 保真"**：故意不改代码、只让 AI 在收尾时**把某条基线断言放宽**（比如不管返回体字段、只看状态码），再跑——你会看到"测试仍全绿"，但这是因为断言被放宽了。**保真确认必须"逐样本 + 与重构前基线同口径"对比，否则全绿没意义。**
