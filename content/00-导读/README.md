## 📍 这本教程是什么 / 不是什么（先读这，再决定要不要读下去）

**这是一本给谁的书**：**开发者与准开发者**——已经会写代码（独立开发者 / 全栈工程师 / 团队多面手 / 想成为开发者的人），能用 AI 生成代码，但面对复杂需求时缺一套**可复用、可验证、可协作**的结构化推进方法，觉得"直接让 AI 改代码，改东坏西、无法验收、难维护"。

**它默认你有基础、内容极度务实**：不教编程入门，不按"入门→进阶→实战"铺内容——那些有更适合的资源。本教程的价值在**深度**，教的是"**如何用判断力应对复杂工程的挑战**"，而非堆砌知识点。

**它的"灵魂"与"载体"（主次分明）**：

- **灵魂 = 判断力**。每个方法的核心，不是"记住这个知识点"，而是回答三个问题：**何时用**这个办法、**怎么在对话里识别 AI 的坑**、怎么把它**剪裁到本轮够用**。举例：别的教程教你"写 Out-of-Scope"，本教程教你"**怎样在对话里逼 AI 把你的边界问出来**"。
- **载体 = 交付物**。产出物锚定、逐条可打勾的验收清单、可复用文档模板——它们的使命是**让判断力落到实处**：逼你在亲手产出一份文档的过程中长出判断，而不是让你带走一堆模板。**模板是为培养判断力服务的，不是目的。**

**它和常见的 AI 教程不在同一座山**：

| 常见 AI 教程                              | 本教程                                               |
| ------------------------------------- | ------------------------------------------------- |
| 产品视角的认知启蒙：教你"想清楚再做"，讲文档长什么样，散文式、知识点导向 | **执行视角的生产力工程**：教你在有限 AI 时间里，稳定地产出**可验收、可复用**的中间产物 |
| 学完留下"**知识**"                          | 学完带走"**可再生的工作能力**"                                |
| 按学习阶段排（入门→进阶→实战）                      | 按"**你手头正在做哪类事**"排（新功能 / Bug / 重构），三条轨道灵魂都是判断力     |
| 承诺"做出一个产品"                            | 承诺"带走一套手艺 + 每份中间产物该长什么样"                          |

> 💡 **一句话**：多数教程教人"做出东西"，**本教程教人"做东西的一套手艺、每份中间产物该长什么样"**——而且这手艺的灵魂，是**判断力**，不是模板。

**为什么它是"三轨专精"、而不是一套通吃**：
多数工程教程要么"一套流程通吃所有事"，要么只讲"新建一个项目"。本教程反其道——把工程里最高频的三类事——**新功能 / Bug 修复 / 重构**——各拆成一条独立轨道。三轨共享同一套判断力内核，但**针对各自痛点各有专属打法**：B1 先澄清需求、B2 先写回归测试、B3 先锁行为基线。**你手头正在做哪类事，就走哪条轨道**，不被通用框架拖累，也不被无关内容稀释。

**六份产物模板 + 验收清单，是你带走的"可再生工作能力"**（索引速查，完整版见下方"产出物索引"表）：

| 你带走的产物    | 在哪章  | 配套验收清单    |
| --------- | ---- | --------- |
| 需求文档（六要素） | B1-① | 三情景验收清单   |
| 技术方案（七段）  | B1-② | 取舍 + 验收标准 |
| 决策记录 ADR  | B1-③ | 决策理由可复看   |
| 任务清单（任务卡） | B1-④ | 每卡可执行、可验收 |
| 实现与验证记录   | B1-⑤ | 结果可复核     |

> 💡 **写给怕"每章先写文档"的人（这是投资，不是仪式）**：真正常用的硬文档，加起来通常**不到一页**，而且 90% 是你在对话 AI 时顺手完成的；它们换来的是"返工前先想清楚"——**一次躲开的返工，通常省回 3 小时**。别把写文档当负担，它是最廉价的判断力训练场。

**配套教学项目就是这套流程的实证**：打开 `refund-shop`，**克隆即跑**（3 条命令启动）。**分支映射（全局唯一口径，正文/导读/GUIDE/README 一律一致）**：**B1 → `b1`**（新功能）；**B2 → `b2-bug`**（修 Bug）；**B3 → `main`**（重构，`b3` 分支已废弃、保留参考勿用）；**`solutions` = 答案对照**；**`main` = 已修复基线**。**同一份代码，切到对应分支就是那条轨道的教学现场**。这就是"三轨专精 + 轻量闭环"最直接的证据。

> 🛡️ **Go 护栏**（先声明，免你白慌）：配套项目用 **Go** 演示，但它承载的是**语言无关的判断力**——"什么时候用哪个办法、怎么识破 AI 的坑、怎么剪裁到本轮够用"，这些换任何语言都成立。**你不会 Go 也没关系**：可以①只跟读原理、把 Go 代码当"伪代码"看；②在练习时用你自己的语言（Python / JS / Java…）写等价版本，命令和工具换成你语言对应的那套。**关键段落**（如 S-D 的命令、B1-② 的代码片段）我会附一句"非 Go 读者"提示告诉你换用什么；其余时候它只是例子，不是门槛。

## ✅ 算不算"有基础"？先花 1 分钟自测

上面说"默认你有基础"——为了不让你误入、也不把会的人挡在门外，这里给一份**软自测清单**（非硬性门槛，纯对照，别吓到自己）。对照下面三档，按你的真实情况打勾：

**第一档 · 硬前置（教程默认你会、不兜底，缺了会卡住）**

- [ ] **读代码**：看到 `if` / 循环 / 函数 / 常用数据结构（数组、字典或对象）、一条 SQL，能大致说出"它在干什么"；不认识的记号会去查，而不是问"这是什么语言"。
- [ ] **跑程序**：装过 Go / Python / Node 之一，会装依赖、能启动一个服务或脚本；代码报错时能看出"哪一行 / 哪个文件"，能把报错信息粘给 AI 而不是空手。

**第二档 · 关键前置（本教程会带你走，但默认你有语法底子；缺了能跟但辛苦）**

- [ ] **改代码**：在已有代码里改一个值、加一个 `if` 判断、加一个函数，而不至于把整个文件推倒重来。你敢改、能改、改完敢跑。

**第三档 · 可引导（本教程内部会从零或浅带，不是硬性准入）**

- [ ] **版本协作**：知道 `commit` / `branch` / `pull` 是什么，知道"改坏了可以回滚"的概念。完全没碰过 git → 本教程 S-D 工具链会带你起步。
- [ ] **Vibe Coding 经验**：已经用 AI 生成过至少一次代码（哪怕只是个小脚本），亲历过"prompt → 代码 → 改"的循环。完全没试过也能跟，只是稍慢。
- [ ] **交付心智**：接受"写出来的东西要能跑、要被验收"，不把"AI 给我一段代码"当终点。这是心态，本教程全程在培养，提前有它更好。

> 💡 **怎么读这份清单**：第一档两条是"别完全小白才进来"的软底线——若连一段代码都读不了、服务都没启动过，建议先花一两天补点编程基础再看本教程。第二、三档即使没打勾，也能跟得上，只是进度稍缓；教程自会带你补齐。**别拿这份清单吓自己**——它的作用是指引你"现在适合读 / 先补一点再读"，不是考试。
> 
> 本教程**默认读者已满足第一、二档**，把预算留给深度与判断力训练。

## 🗺️ 推荐阅读路径（先看这个，别从头全读）

> 本教程**不是**一本从头读到尾的书，而是一条"按需取用"的路径。**别照目录从上往下读**——那会先啃完所有共享单元再动手，认知负荷最大，也违背"先跑通、共享单元被引用时才读"的初衷。

**先照这三行起手（新手照做即可，别多读）**：

- **① 读 `S0·为什么需要流程`**（必读，20–40 分钟）——先明白"为什么要这套流程"。
- **② 读 `S-对话·与AI高效多轮对话`**（上手就来，10 分钟）——学"怎么跟 AI 谈不崩"。
- **③ 按你手头的活选轨道**：新功能/新项目 → **B1 主线 ①→⑤**；修 Bug → **B2**；重构 → **B3**。

**完整路径表（顺着行号走即可）**：

| 顺序  | 读什么                                           | 花多久          | 什么时候读                                   |
| --- | --------------------------------------------- | ------------ | --------------------------------------- |
| 1   | S0 · 为什么需要流程                                  | 20–40 分钟     | 开始前，必读，先建立"为什么要流程"的共识                   |
| 2   | S-对话 · 与AI高效多轮对话                              | ~10 分钟       | 紧接着读，学会"怎么跟 AI 谈不崩"再动手                  |

## 📖 读不懂？用 AI 帮你读本教程

> 本教程无法把所有概念都嚼碎喂给你——过度解释会膨胀正文、反伤阅读。**更好的办法：把任意一段原文丢给你的 AI 工具，用下面的话术让它替你重讲、举例、考你。** 下面 6 条**照抄即用**，把 `[占位]` 换成你要问的那一节/那个词即可。读教程时卡住，先来这里抄一句，别自己硬猜。

**先看一条实际对话长什么样**（用 ① 试，读 `B1-① 目标二 · 验收三情景` 时卡住）：

> **你**：请把「B1-① 目标二 验收三情景的'正常路径/边界路径/异常路径'」用大白话重新讲一遍，别用术语，多给个生活例子。
> **AI**：就是说——检查一个功能做对了没，别只测"顺顺当当"那一种情况。
> 
> - 正常路径：一切正常时它该怎样（像退全款，钱得原路退回）；
> - 边界路径：刚好卡在临界点怎么办（退款额刚好=订单额→全退；少一毛→部分退）；
> - 异常路径：乱来/失败/连点两下时怎么扛（退超剩余金额→拒绝；重复点退款→不能扣两次钱）。
>   一句话：**顺的、卡的、出岔的，三种都得想**。

> 看到没——它给你的是**换成人话的归类+例子**，不是又抛术语。下面 6 条都是这个套路。

> 💡 **顺手点破"核验三问"**：这一整块"用 AI 帮你读教程"，本质就是在练本教程的灵魂——**判断力**。每次把原文丢给 AI 时，脑子里带三问：**①它这句话真的对吗？（别被顺理成章骗过）②它是不是只说对了一半？（漏了坑）③换个场景它还成立吗？（能不能剪裁到我这轮够用）**。而 **`S-附录 · 全量提示词模板库` 正是这套判断力的自查工具**——走到哪一步卡了、不确定自己判断对不对，去那查对应提示词，用它把模板换成你的场景，你就知道自己在往哪个方向使劲了。

**① 这节读不懂 → 让 AI 用大白话重讲**（什么时候用：通读一遍没懂。为何有效：换表述 + 带生活例子，跳过术语障碍）

> 请把「`[某节标题]`」这段内容用大白话重新讲一遍，别用任何术语，尽量多给一个生活化的例子。

**② 术语 / 名词不明 → 让 AI 解释并"考"你**（用：单独一个词卡住。为何有效：AI 既讲清楚，又问一句确认你真懂，防止"我以为会了"。**你会得到一个"定义 + 例子 + 反问你一句"**）

> 「`[状态机]`」这个词是什么意思？先给一句大白话定义，再举一个订单退款的例子，最后**问我一个问题**确认我真的理解了。

**③ 两概念易混 → 让 AI 对比**（用：分不清两个很像的概念。为何有效：对比 + 给出具体的混淆触发点，比单独记定义牢固。**你会得到一张对比表，并标出你最可能点错的那一处**）

> 「`[幂等]`」和「`[状态机]`」有什么不同？各自给一个我**容易混淆**的场景，帮我把它们分清。

**④ 检验我理解得对不对（费曼）→ 让 AI 只挑错、不说好话**（用：觉得懂了但不自信。为何有效：逼自己把理解讲出来，AI 只负责纠错，最能暴露漏点。**你会得到一份"你的理解 vs 正确版本"的逐条差异**）

> 我说一下我对「`[某概念]`」的理解：`[你的话]`。你**只许挑错和补漏，不要夸我**，把我不对的地方逐条列出来。

**⑤ 想记住 → 让 AI 出 3 选 1 小题考我**（用：想自测记忆。为何有效：主动回忆比重复阅读记得牢。**你会先做一题，再收到"你这题暴露了你哪没懂"的点评**）

> 针对「`[某节]`」出一道上题 3 个选项的选择题考我，我答完后，告诉我哪一句说明我哪部分还没懂。

**⑥ 把散落的几节连成整体 → 让 AI 串成图 / 故事**（用：学完感觉碎片化。为何有效：把孤立知识点串成可记忆的骨架。**你会得到一张流程/故事，让这些点不再各管各**）

> 把「`[这几节]`」串成一个流程图，或讲成一段我能一遍记住的小故事，让我知道它们是怎么连起来的。

> 💡 **兜底**：如果上面某条你用起来没效果，往往是"你喂给 AI 的原文太短/太长"。**喂更精准的原文段落**，或回看 **S-附录顶部的 🧭 新手术语速查**（每词一句大白话）。这是"用 AI 读教程"的总开关——**一切解释都该先问 AI，而不是先翻遍全文找答案。**

> **正文字章"卡壳救助"已收拢于此处**：正文不再逐章铺卡壳救助块；你读任何一章被卡住，就回这里**抄一条上面的话术**（① 读不懂→大白话重讲 / ② 术语→解释并考你 / ⑤ 想记住→出小题考我），把「`[某节]`」换成你卡住的那一处，丢给 AI 即可。补一句纪律：**卡壳不是病，硬猜才是**——先抄一句丢给 AI，别在原文里空转。

## 🛠️ 命令速查 + 报错自救（正文里每遇到一条命令的首现，都在这里对一下）

> 本教程各章会反复出现几条命令。**同一条命令第一次出现的地方，就先看下面这一行，知道它"在做什么"**——报错别慌，下面也给了每条的"最常见报错 + 自救一句"。**命令的实际用法 + 哪一步在哪条轨道用，仍以各章正文为准；这里是"看命令不懵、报错不求人"的速查**。**非 Go 读者**：下面这些 Go 命令，换成你语言对应的"跑测试 / 编译 / 跑服务"命令即可（如 Python 的 `pytest` / `uv run`、JS 的 `npm test` / `npm run dev`）；判断力部分是通用的。

| 命令                                          | 它在做什么（一句白话）                         | 最常见的坑 / 报错自救一句                                                            |
| ------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------------- |
| `go run .`                                  | 把当前目录这个 Go 程序**编译并跑起来**             | 已在你跑别的服务占住端口时 → 换端口或关掉旧进程；找不到入口 → 确认在含 `main.go` 的目录跑                     |
| `go build ./...`                            | 把整个工程**编译一遍**（不跑），检查能不能编过           | 报"undefined: xxx" → 那个函数/变量拼错或没 import；记住"编译错多数是改名/漏引用，不是逻辑错"             |
| `go test ./...`                             | **跑整个工程所有测试**，红/绿一目了然               | 报"build failed" → 先编译错；报"FAIL: TestXxx" → 某条断言没过，看那行 log；别把"测试写错"当"功能坏了"  |
| `go test ./internal/routes/ -run ^TestXxx$` | 只跑某一个测试（后面是跑的包和测试名）                 | 忘了 `-run` 就会跑一堆；测试名要跟函数名完全一致                                              |
| `go vet ./...`                              | **静态检查**（帮你抓低级风险，不是跑逻辑/调用链）         | 它不是报"哪里调错了"，是报"你代码里潜在的危险写法"；看不懂就把它当成"第二双眼睛"                               |
| `git checkout <branch>`                     | **切换分支**（如 `b2-bug`），你的"三条轨道现场"就靠它切 | 提示文件冲突/未提交 → 先 `git stash` 或提交，再切；切过去看不到预期代码 → 确认分支名拼对                    |
| `git status` / `git diff`                   | 看`改了什么 / 和上一版差多少`                   | 没输出 ≠ 没改，可能是没 add；`git diff` 只显示未暂存改动                                     |
| `git commit -m "…"`                         | 把当前改动**存成一个版本**（留个能回滚的存档点）          | 提示"nothing to commit" → 先 `git add`；写清楚 commit 信息，改坏了才好 `git checkout` 找回 |

> 💡 **报错三大自救句（比拼命读报错更省事）**：
> ① 报错看不懂 → 把**整段报错原文**贴给 AI："这段报错是什么意思？可能哪三处引起的？"
> ② 跑不起来 → 报错抄给 AI 前，先自己看**最后一行**是不是"文件:行号"，那是定位线索，别丢。
> ③ 修完没变化 → 很大概率是**没重新编译/没重启**（`go run` 每次重新编译，但别的依赖要 `go mod tidy`），先做这两件再怀疑代码。
> 
> 这条"报错自救"同样通用于一切工具：**报错是线索不是敌人**，喂给 AI 比硬啃快。

## 😰 M-01 当心：AI 会一本正经地给「看着对、其实跑不了」的东西

> 判断力的第一课，就是**别全信 AI 给的答案**。读完本教程，你要练的不只是"让 AI 做得更多"，还有"看出它什么时候在瞎编"。AI 的"乱答产出"主要有 3 张脸：

| 它长什么样    | 怎么一眼/一跑就识破                                                      |
| -------- | --------------------------------------------------------------- |
| **貌似正确** | 条理清晰、名词头头是道，但凑近看逻辑不住脚（如"幂等键=随便一个码"）→ **看到结论先问"凭什么"**            |
| **跑不了**  | 让你抄的代码/命令一执行就报错（缺 import、缺依赖、文件路径写错）→ **每给一段可执行的东西，先想它会报什么错再跑** |
| **会崩**   | 单独看对，一到真实数据/边界就崩（忽略了 0 元、并发、超限）→ **做完了，用"异常/边界/并发"三情景各砸一下**     |

> 💬 **3 条兜底话术**（发现 AI 在乱给时，任选一句把它拽回来）：
> ① 「这段结论我看着对，但**你凭什么觉得它成立？给得出依据或反例吗？**」
> ② 「把要粘贴内容**先按你理解了的样子复述一遍**，并指出哪里最容易跑不通，再贴给我。」
> ③ 「**换个更保守做法试**：你先给我一个最不容易出错的版本，我们再往里加复杂度。」

> 这三张脸和三条话术，正是全教程处处强调的"识别 AI 的坑"的最小样板——**它不是只在这节有用，而是贯穿所有轨道**。
